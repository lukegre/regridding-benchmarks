Chunk layout and execution

The completed experiments use a 4 × 512 × 512 field cube with four time slices, 256 missing values, and in-memory NumPy inputs wrapped as Dask chunks. They run the same fixture with different input chunk layouts. Graph construction and actual computation are timed separately when the adapter returns a lazy array; for eager outputs the application time is reported separately. Setup is shared across repeats and is not included in those times. Use the filters to compare a tool, test and layout.

Interpretation and limits

Chunk boundaries are an execution choice, not a change in interpolation method. The recorded input and output chunk tuples, scheduler, task counts and rechunk graph layers are shown for each profile. xESMF was explicitly given full-horizontal 512 × 512 output chunks in the completed experiments. Some adapters may materialize data eagerly or rechunk spatial dimensions; lazy input alone does not establish out-of-core execution. Results reflect these fixtures, library versions and scheduler on the recorded machine, not a general memory-scaling guarantee. Maximum absolute and seam errors compare against the recorded reference; finite-mask mismatches should also be checked.
