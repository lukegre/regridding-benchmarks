Setup and interpolation at realistic sizes

All packages in a test receive identical source coordinates, destination coordinates and scalar values, verified by SHA-256 fingerprints of the canonical inputs. Adapters may normalize equivalent longitudes, reorder storage, or convert native geometry formats without changing the physical grid. Common 512 and 1024 scales, plus a 4096 scale for all CRS adapters, are run serially with one thread and three repetitions. Package imports, a small warmup, and input generation are outside the timers.

Methodology, geometry and timing boundaries

The 10-second target guided the shared workload sizes; timers are never padded and sizes are never adjusted per package. Some packages remain below one second on the same inputs. Repetitions rebuild the adapter. All three individual measurements are downloadable; the report shows arithmetic means and observed min/max, not confidence intervals.

Rectilinear/ROMS rasters use n×n source cells and n×n destinations. Gaussian sources use n×2n cells; HEALPix uses NSIDE=n/2; icosahedral sources are deterministic triangulated icospheres. Those global families share an aligned, regular destination raster between approximately 80°S and 80°N. TempestRemap and ESMPy use the same actual source triangles as the other icosahedral adapters.

Both CRS cases use the same WGS84 raster across packages and fixed, shared target geotransforms: EPSG:4326 → EPSG:2056 (Swiss LV95) and EPSG:4326 → EPSG:3857 (Web Mercator). Rasterio, rioxarray and odc-geo resample values; pyproj only transforms coordinates. Xugrid has its own local projected triangular-mesh test family and is not compared directly with raster destinations.

Setup includes API wrapping, spatial search and reusable weight construction where exposed. SciPy/xarray/raster warp/UXarray/MIR interfaces perform some geometry work during application; their split must not be interpreted as a pure weight-build timer. MIR uses a fresh process and a fresh cache directory for each recorded repeat; the original cached-call observations are retained separately in cache controls. NCO applies TempestRemap-generated weights, so its setup is the TempestRemap workflow rather than an independent weight algorithm. CDO/Tempest/NCO file preparation and Python output reads are recorded separately and subtracted; native executables still contain file I/O. Timings include no accuracy calculation or output hashing.

Accuracy is measured against the same analytic field as the small-grid survey. Conservative source values are centre samples, not exact analytic cell averages. Coverage, geometry and kernel choice must be considered alongside speed. The hardware quota is two vCPUs and 8 GiB RAM; the timed worker uses one thread. No packages are benchmarked concurrently, and memory exhaustion is not a test objective.
