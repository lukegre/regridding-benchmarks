## ICON source snapshot procedure

The public catalogue inspected on 2026-11-19 resolves `ngc3028` to the DKRZ filesystem path `/work/kd1453/rechunked_ngc3028/ngc3028_P1D_7.zarr`: `P1D` is the current catalogue default and `7` is the notebook selection. The observed SHA-256 of the root catalogue was `7f3ce7c43c98d6a52361578c21ceed428d284a6f978d767749c9571fcfd611eb` and of its `ICON/main.yaml` was `c5a8571ce34923bbcea0c76cb778b5a99c1361be824b2da6ac9c71e44c960205`. These hashes identify catalogue bytes only; they do **not** pin the Zarr data. Both catalogues and store can change.

On a DKRZ host with access, retain those catalogues and record their hashes and retrieval time. Open the consolidated store with xarray, select `to.isel(time=0, depth_full=0)` and load the full 196608-cell field, retaining source time, depth, units, CF grid mapping, nested order and missing-value mask. Export the selected field to a single NetCDF file, record the software versions and original store metadata, then hash the exact exported bytes with SHA-256. Verify time, shape, nside and order against the notebook and inspect missing-value encoding before registering the resulting digest and a permitted durable URL. A file's byte hash identifies that snapshot; different writer versions may encode numerically identical data differently. Until the file is obtained and its provenance and redistribution terms checked, the case remains unavailable.

## xHEALPixify smoke environment

The image installs the exact source revision into a separate interpreter using `environments/requirements-xhealpixify-linux-x86_64.lock`. Set `BENCH_XHEALPIXIFY_PYTHON` to select that interpreter in a local installation. The adapter checks for `8ebd09eb7` in the installed version recorded by setuptools-scm. The fixture deliberately stays regional because upstream interpolation does not handle global, polar or antimeridian targets. Setup includes first-use Numba compilation and application includes materialization. The pinned mask implementation emits an invalid-divide warning for empty targets, which the test checks are missing.

## MUR coastal xHEALPixify case

The pinned input is a NOAA CoastWatch ERDDAP CSV subset of NASA JPL's MUR v4.1 Level-4 *analysed* SST, not a direct single-sensor observation. It contains `analysed_sst` and `mask` at 2020-01-01 09:00 UTC over 35–39°N, 124–120°W, on the original 0.01° grid (401 × 401). Its URL and SHA-256 are in `datasets/mur-sst.json`; two requests on 2026-11-19 yielded the same digest. [NOAA metadata](https://coastwatch.pfeg.noaa.gov/erddap/info/jplMURSST41/index.html) states that older data are sometimes revised; a changed response will fail checksum verification. The same metadata describes mask bit 1 as open sea and bits 2, 8, 16 as land or ice. This case requires finite SST and open sea, excluding those land and ice bits. NOAA describes the data as freely usable and redistributable under the JPL PO.DAAC policy; raw data are not stored in this repository.

The xHEALPixify case uses nested nside-512 cell centres inside 35.1–38.9°N, 123.9–120.1°W. A regular-grid four-corner baseline applies the same three-valid-vertex threshold and renormalization, checks support and values, and a large sentinel in masked source cells detects leakage. In the verified run, 410 of 882 targets were wet, 472 missing and four partially masked. The maximum common-support difference was 3.6e-15 °C. The test uses `MUR_TEST_CSV` and the pinned interpreter. Setup includes first-use Numba compilation.

The tile cases derive a regional 128-pixel-block COG without overviews from the same checksum-verified CSV. The fixture phase includes conversion. Each case reads the same cropped source window from the file and from GDAL's HTTP range reader, then warps it to a 256 × 256 XYZ tile. Both paths read a recently written file with warm OS page cache and a fresh worker. The HTTP server runs on loopback in that worker. The documented peak RSS includes both paths and the server. All three zooms passed exact agreement on masks and values and made range requests. These tests measure protocol and driver overhead with the file close to the reader. A remote COG hosted at an immutable object URL is needed to measure WAN or object-store performance.
