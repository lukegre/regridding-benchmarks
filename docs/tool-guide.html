Which tool for which data?

Choose by data meaning and geometry before comparing speed. A method that returns numbers is not necessarily valid for your quantity. This guide summarizes documented roles and the specific synthetic adapters tested on 2026-11-17; it is not a guarantee for every version or input.

Non-float data: choose by semantics, not dtype

Native acceptance of integer arrays does not preserve classes or totals. Define the output meaning first.

MeaningSchemeAvoid
Categorical identifiers or stringsNearest class, with an explicit choice between selecting the nearest cell and retaining its validity versus searching for the nearest valid cell; or an explicitly defined area/distance-weighted mode. Availability of nearest-valid search depends on the tool. Define deterministic ties and an unknown class. Encode labels to integer IDs with a reversible lookup; preserve nodata in a separate validity mask. Use compact codes for identifiers too large for exact float representation (including integers above 2^53); retain the original labels in the lookup and never cast them through float.Never bilinear-interpolate class IDs or round blended labels.
Ordinal valuesUse nearest or mode when ordered labels are classes; interpolate only when distances on a numeric scale are meaningful and the resulting values are valid for the application.Do not assume equal spacing between ordinal ranks.
Continuous quantity stored as integerConvert to floating point and use a continuous method appropriate to geometry, error and conservation; retain scale/offset and units. For CF-packed values, decode scale_factor/add_offset and missingness before interpolation; repack only with an explicit precision and overflow policy.Storage dtype alone does not make a quantity categorical; integer output can lose precision.
Extensive counts or totals per cellDistribute totals by conservative overlap fractions using cell areas and valid coverage; equivalently remap density then multiply by destination area with consistent normalization. Retain fractional output or use globally constrained rounding if integer totals are required. Ensure areas, masks, covered domain and normalization refer to the same geometry; check total over the common covered domain. For partially covered cells, a coverage-normalized average multiplied by full destination area is not generally conserved; use actual covered area with consistent source and destination masks.Never independently round each interpolated count or assume a weighted average preserves sums.
Boolean occupancyUse nearest for a sampled state; mode for dominant class; any/all for stated presence semantics; or area fraction as floating point for coverage. Threshold fractions only if an explicit decision threshold is meaningful.Do not choose any/all, mode or fraction interchangeably.
Packed bit flagsNearest for a representative observation, or unpack each bit and apply documented per-bit any/all/weighted rules; repack after aggregation.Never average or bilinearly interpolate packed flags.
TimestampsSpecify whether values denote instants, intervals or categorical event times, calendar/time zone and missingness; interpolate only when a meaningful temporal model permits, after conversion to a suitable numeric time axis. Use a relative time origin and suitable precision to avoid loss of precision, then restore the calendar and units.Do not blend date encodings blindly or treat intervals as point instants.

Before running

  • Identify source and target geometry, CRS/frame, units, shape and field location before choosing a tool.
  • Validate coordinates, uniqueness and order, longitude seam, dimensions and valid topology. Validate actual corners and areas for conservative operations.
  • Separate geometry masks from per-variable missing values; reserve a collision-free sentinel or use a separate valid mask.
  • Determine intensive versus extensive quantity, coverage, normalization, extrapolation, valid output domain and deterministic tie behavior.
  • Test identity, constant, known category and missing-value cases; check finite coverage, edge behavior and area integrals when applicable.
  • For reused weights, hash coordinates, topology, bounds, masks, method and periodicity; do not reuse by shape alone.
  • For chunked data, distinguish lazy graph construction, weight generation and actual compute; account for rechunking and peak memory.

Geometry, missing data and execution

For a cell-average intensive quantity, conservative weights generally preserve the area integral over the covered domain, subject to geometry, masks and normalization. For cell totals, divide by source area, remap consistently and multiply by destination area, or use explicit overlap fractions. Compare integrals over the same covered region.

A grid mask defines geometry excluded when weights are built; a per-variable NaN or nodata describes missing field values. They can have different effects. State how partial destination coverage is normalized and whether unmapped cells are missing or extrapolated.

Chunks are an execution strategy, not geometry. A lazy graph is not a computed result. Weight generation, source windows, spatial rechunking and output materialization can dominate memory; verify the exact package version and operation with realistic chunks. See the Large & chunked report for measured cases; absence of a test is not evidence of support or non-support.

Source/destination coordinate systems and units must agree with the operation. Do not infer spatial compatibility from equal array shapes. Validate periodic longitude, unique coordinates, corner orientation and non-self-intersection. Record any datum transformation and axis order.

The large regional TempestRemap overlap generation profiles timed out at 300 s; NCO depended on those same weights. Small native icosahedral-to-raster tests succeeded. This does not establish that NCO application or global meshes are unsupported.

Runnable categorical example

This nearest-neighbour example selects the nearest source cell, including its validity; it does not search for the nearest valid cell.

# Categorical IDs: keep a separate valid mask and never blend labels.
import numpy as np
from scipy.interpolate import RegularGridInterpolator
lat = np.array([0., 1.]); lon = np.array([10., 11.])
classes = np.array([[1, 2], [1, 2]])  # 1=forest, 2=water
valid = np.array([[True, True], [True, False]])
query = np.array([[0.2, 10.8], [0.9, 10.9], [3., 10.]])  # lat, lon
lookup = RegularGridInterpolator((lat, lon), classes, method="nearest",
                                 bounds_error=False, fill_value=-1)
valid_at = RegularGridInterpolator((lat, lon), valid.astype(float),
                                   method="nearest", bounds_error=False, fill_value=0)
result = lookup(query).astype(int)
result[valid_at(query) == 0] = -1  # explicit unknown; -1 is not a valid class
# result: [2, -1, -1]; retain a reversible ID-to-label table.

Per-tool input contracts

Expand a tool for input shape, geometry, missing data, execution, tested scope and limitations. These are advisory descriptions; consult the linked primary documentation for your version. Download the machine-readable contracts.

CDO
Use for
Climate-file remapping of structured, Gaussian and supported unstructured grids.
Required input
CF-like NetCDF/GRIB variables with horizontal dimensions and grid metadata; choose a compatible target grid description. Dimensions and data order must match the declared grid.
Geometry and units
Geographic centres in degrees; provide cell vertices/bounds for conservative work and correct grid type/order, seam and periodicity.
Mask and missing data
Set file missing values and grid masks deliberately; inspect target coverage and normalization.
Execution and chunking
CLI consumes and writes files; weight generation and application can be separate. File I/O is materialized.
Tested adapter
Nearest, bilinear and conservative adapters across the synthetic families; not every grid/method combination succeeded.
Non-float method choices
For supported grids, use remapnn / gennn for nearest class sampling; verify method/grid compatibility. Weighted category mode or flag aggregation needs an explicit workflow.
Limits and fallback
Bilinear on the tested triangular mesh was rejected. HEALPix conservative aborted without --force because edges are not great circles; forcing is not proof of exact conservation.
Primary documentation
https://code.mpimet.mpg.de/projects/cdo/embedded/index.html
xESMF
Use for
Rectilinear or curvilinear latitude/longitude grids, reusable weights and conservative remapping.
Required input
xarray Dataset/DataArray grid with lon/lat 1-D axes or matching 2-D centre arrays in degrees; field horizontal dimensions match grid. Destination has corresponding coordinates.
Geometry and units
Conservative methods require valid cell corners/bounds (lon_b, lat_b or supported CF bounds); check orientation, topology and partial coverage. Set periodic for appropriate global non-conservative grids; handle seam consistently.
Mask and missing data
Grid mask uses ESMF convention 1 valid, 0 masked. It is distinct from per-field NaNs; choose skipna and normalization policy explicitly.
Execution and chunking
Weights may be reused; key them by all coordinates, corners, masks, method and periodicity, not shape. Dask data application is supported; weight construction and spatial chunk behavior depend on version/method. The chunked benchmark explicitly sets output_chunks={'y': 512, 'x': 512}; it does not demonstrate spatially distributed output. In a separate 1024×1024 default-output pilot, 128×128 input chunks produced a warning of 64× more output chunks and the pilot was stopped after about 150 seconds without completing; this is not a completed timing.
Tested adapter
Bilinear, nearest_s2d and conservative on supported structured grids, including ROMS corners.
Non-float method choices
Use method='nearest_s2d' for source-to-destination nearest classes. Weighted mode, bitwise rules and count conservation require a separate explicit workflow; do not use bilinear for labels.
Limits and fallback
Our adapter did not exercise general unstructured xESMF. Missing/folded corners and stale weights can fail or silently degrade results. Scalar remapping does not rotate vectors.
Primary documentation
https://xesmf.readthedocs.io/en/latest/user_api.html · https://xesmf.readthedocs.io/en/latest/notebooks/Masking.html
GDAL / Rasterio
Use for
Affine GIS rasters, CRS changes; geolocation-array warping for suitable swaths.
Required input
Raster bands or NumPy arrays with spatial rows/columns, source and destination shape, CRS and affine transform; or explicit 2-D geolocation arrays for the supported warp path. Rasterio geolocation path used CRS objects.
Geometry and units
Provide CRS as EPSG/WKT/CRS object, transform mapping pixel coordinates to CRS coordinates and destination grid. Respect pixel-centre/edge convention; avoid discontinuous longitude for a dateline swath.
Mask and missing data
Set source and destination nodata or masks explicitly; valid pixels and numeric sentinels must not collide.
Execution and chunking
Warp is an eager native operation in tested Rasterio calls; file-backed/windowed workflows need sufficient source overlap and their own memory plan.
Tested adapter
Affine raster reprojection and a separate geolocation-array swath path.
Non-float method choices
Use rasterio.enums.Resampling.nearest or, where supported and appropriate, Resampling.mode. Check tie, nodata and footprint behavior for the installed GDAL version.
Limits and fallback
A swath is not an affine raster; geolocation handling needs explicit support. Dateline coverage was sensitive to longitude continuity. Resampling kernel is not automatically area-conservative.
Primary documentation
https://rasterio.readthedocs.io/en/stable/topics/reproject.html · https://gdal.org/en/stable/programs/gdalwarp.html

ECMWF-style Gaussian and HEALPix grids with authoritative grid specifications.
Required input
A named xarray DataArray with geographic coordinate metadata for the tested high-level path, or a supported MIR/earthkit field and explicit input/output gridspec. Values must follow gridspec order.
Geometry and units
Specify Gaussian grid parameters or HEALPix nside/order as appropriate; coordinates and grid definition must agree. Select a supported destination specification.
Mask and missing data
Define missing data according to the field and interpolation configuration; verify output coverage.
Execution and chunking
Tested calls materialized output; caches and native setup affect timing. Chunked/lazy behavior is API- and version-specific, not established by this adapter.
Tested adapter
Full Gaussian and HEALPix high-level xarray/MIR workflows.
Non-float method choices
Choose a documented nearest-neighbour interpolation supported by the exact gridspec and installed MIR version; verify the configuration and class preservation. Otherwise use a suitable nearest-capable tool.
Limits and fallback
Other families were not exercised by this adapter. The installed high-level xarray path required earthkit-utils and named geographic metadata.

Pyresample
Use for
Geolocated swaths or irregular point centres to another swath or area, using neighbour search.
Required input
SwathDefinition with matching 1-D or 2-D lon/lat arrays and data shape, or an AreaDefinition with CRS, extent and shape; target needs an equivalent geometry. Geographic lon/lat are degrees. Scan-based or EWA workflows can impose additional 2-D layout requirements.
Geometry and units
Use longitudes in the documented −180…180 convention and valid latitudes. Specify radius of influence in metres and neighbour/weight parameters. Search uses centres, not cell polygons.
Mask and missing data
Set fill value or masked output; decide whether invalid samples are dropped before search. Radius can extrapolate beyond the observed footprint.
Execution and chunking
Neighbour info may be reused for matching geometry. Dask-capable APIs exist but vary by algorithm; tested standard adapter was eager.
Tested adapter
Nearest and Gaussian centre-based sampling on all six source families.
Non-float method choices
Use kd_tree.resample_nearest for nearest class sampling with an explicit radius and fill value. Gaussian weighted averaging is not a class mode.
Limits and fallback
Does not make a centre-based nearest/Gaussian sample conservative; use polygon-aware remapping for area integrals.
Primary documentation
https://pyresample.readthedocs.io/en/latest/howtos/swath.html · https://pyresample.readthedocs.io/en/latest/howtos/geometry_utils.html

Dask-aware xarray reprojection of affine, georeferenced rasters.

xarray DataArray with spatial y/x dimensions and a valid GeoBox (shape, affine transform, CRS); provide destination GeoBox and resampling.

Source and destination CRS, pixel geometry and spatial dimension order must agree with array coordinates.

rioxarray
Use for
xarray-facing GIS rasters, CRS metadata and reprojection.
Required input
DataArray/Dataset with identifiable x/y spatial dimensions, CRS (for example rio.write_crs) and transform/coordinates; specify destination CRS or matching raster.

SciPy RGI / xarray.interp
Use for
Simple point interpolation on rectilinear axes, including full Gaussian latitude arrays.
Required input
RegularGridInterpolator: strictly ascending or descending 1-D coordinate axes and values with matching leading dimensions; target points in axis order and units. xarray.interp: named dimensions and coordinate labels.
Geometry and units
Coordinates need not be evenly spaced but must be monotonic and unique. Explicitly normalize longitude and extend a cyclic column for global seam interpolation.
Mask and missing data
Define bounds_error/fill_value or xarray extrapolation policy and propagate missing values intentionally.
Execution and chunking
SciPy RGI consumes in-memory numerical arrays in the tested path. xarray may operate on Dask arrays depending on method and chunks; verify compute/memory for the installed version.
Tested adapter
Linear and nearest structured-axis interpolation including full Gaussian grids.
Non-float method choices
Use RegularGridInterpolator(..., method='nearest') or xarray.interp(..., method='nearest') for numeric codes; encode labels compactly and retain the validity mask. Neither provides conservative overlap.
Limits and fallback
Not a CRS transformer, 2-D curvilinear grid, polygon overlap or conservative remapper. Interpolate only after coordinating CRS and units.
Primary documentation
https://docs.scipy.org/doc/scipy/reference/generated/scipy.interpolate.RegularGridInterpolator.html · https://docs.xarray.dev/en/stable/generated/xarray.Dataset.interp.html
Healpy / astropy-healpix
Use for
Native HEALPix indexing, interpolation or resolution changes.
Required input
One value per pixel with length 12 × nside²; record valid nside, RING or NESTED order, frame and units. astropy coordinates use astropy units/SkyCoord; healpy angular APIs may use theta/phi radians or lonlat degrees.
Geometry and units
Source ordering must match declared order; targets must use the same coordinate frame. Wrap target longitude consistently and handle the seam. Validate nside for the selected order (for example healpy.isnsideok(nside, nest=True)); NESTED requires a power-of-two nside.
Mask and missing data
Healpy UNSEEN/masks and NaNs require explicit handling; preserve validity separately from data.
Execution and chunking
Tested native operations use materialized arrays. Resolution changes need an explicit intensity versus total scaling policy (healpy ud_grade power).
Tested adapter
Healpy and astropy-healpix interpolation on HEALPix; Healpy resolution scaling control.
Non-float method choices
For classes, use healpy.ang2pix and gather by pixel index or astropy-healpix coordinate-to-index and gather; do not use bilinear interpolation of codes. Match nside, order and frame.
Limits and fallback
Wrong ordering returned plausible wrong values. In the installed astropy-healpix path negative longitudes produced huge finite values; wrapping to 0…360 fixed that control. Verify installed version and longitude behavior.
Primary documentation
https://healpy.readthedocs.io/en/latest/generated/healpy.pixelfunc.ud_grade.html · https://astropy-healpix.readthedocs.io/en/latest/
ESMPy
Use for
Topology-aware spherical grid or mesh remapping, including conservation.
Required input
ESMF Grid or Mesh and Fields at the correct centre/node location, with compatible source/destination dimensions and geometry; add node coordinates, IDs, element types and connectivity for a mesh.
Geometry and units
Supply valid spherical coordinates, element connectivity and corner geometry; in our Mesh adapter connectivity used zero-based local node indices independent of node IDs. Check API/version and decomposition.
Mask and missing data
ESMF grid/mesh masks and unmapped destination policy are separate from field NaNs; define area/coverage normalization.
Execution and chunking
Weight construction and application are separate; native arrays are materialized in the tested serial adapter. Parallel decomposition is outside these tests.
Tested adapter
Conservative closed spherical triangular mesh remapping with integral checks.
Non-float method choices
Select a documented nearest source-to-destination regridding method for compatible field locations; verify the installed ESMPy API and grid/mask support. Use conservative overlap plus area handling for totals.
Limits and fallback
A mesh of points alone cannot provide conservative cell overlap; validate geometry and source/destination field locations.
Primary documentation
https://earthsystemmodeling.org/esmpy_doc/release/latest/html/
TempestRemap / NCO
Use for
Offline spherical mesh overlap weights and file-based weight application.
Required input
TempestRemap source/destination mesh files with node coordinates and cell connectivity, plus field data in compatible NetCDF dimensions/order. NCO applies compatible generated map weights to a matching file.
Geometry and units
Use valid non-self-intersecting cells, matching topology and coordinates; check mesh area, orientation, coverage and map normalization.
Mask and missing data
Encode missing data and masks separately; our weight application propagated NaNs to affected targets. Define unmapped-cell policy.
Execution and chunking
Native command-line mesh/map generation and file-based application; setup and apply can be reused separately. Tested workflow materializes files.
Tested adapter
TempestRemap conservative mesh-to-mesh and mesh-to-raster; NCO applied the same maps and matched outputs.
Non-float method choices
For classes, apply only a map known to encode the desired nearest or categorical aggregation rule; these tested conservative weights average values and are not category mode. Use a nearest-capable tool if necessary.
Limits and fallback
NCO is a weight application path here, not independent weight generation. Conservation depends on geometry and normalization; arbitrary NaN gaps need explicit handling.
Primary documentation
https://climate.ucdavis.edu/tempestremap.php · https://nco.sourceforge.net/nco.html#ncremap

UGRID mesh manipulation and local planar mesh interpolation/overlap.

iris-esmf-regrid

Iris Cube with horizontal coordinates and field dimensions aligned to source grid; supply a compatible target Cube/grid and coordinate system.

pyproj
Use for
Transform coordinate points between CRSs; prepare geometry for another remapper.
Required input
Source and destination CRS as EPSG, WKT or pyproj CRS; coordinate arrays in the source CRS units, with matching shapes.
Geometry and units
Use Transformer.from_crs(..., always_xy=True) when passing x,y or lon,lat; longitude/latitude degrees for geographic CRS, projected coordinates in CRS units.
Mask and missing data
Check input validity and transformation errors (errcheck=True); propagate validity independently.
Execution and chunking
Coordinate transformations use eager arrays in the tested path; batch points if needed.
Tested adapter
EPSG:4326 to EPSG:2056 and 3857 point transforms with round-trip checks.
Non-float method choices
No value interpolation method: transform the coordinates, then choose a separate nearest, categorical aggregation or conservative remapper according to semantics.
Limits and fallback
Does not resample raster values, calculate overlap, or conserve totals; combine with an appropriate raster or mesh remapper.
